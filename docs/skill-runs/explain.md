# Пример вызова `/explain`

**Механика:** аргументы. Скилл получает цель объяснения через `$ARGUMENTS`:

```
Объясни, как устроено: $ARGUMENTS
```

**Вызов:** `/explain TaskBoard.tsx`

## Результат

## Как устроен `TaskBoard.tsx`

1. **Назначение.** Это главный экран доски. Он хранит список задач и всё состояние интерфейса: какая форма открыта, какое подтверждение ждёт ответа, какие ошибки показать. Сам он задачи не рисует, а раздаёт данные дочерним компонентам.

2. **Откуда данные.** Компонент получает `repository` (интерфейс `TaskRepository`, `src/services/taskRepository.ts:8`) и при первом показе вызывает `repository.load()` (`src/components/TaskBoard.tsx:33`). Как именно хранятся задачи, он не знает: сейчас это `localStorage`, а в тестах — дублёр.

3. **Как меняет данные.** Каждое действие сначала сохраняется через репозиторий, и только потом обновляется локальный список `tasks`:
   - создание и редактирование — `saveTask`;
   - смена статуса — `moveTask`;
   - удаление и сброс — `confirmAction`.

   Если сохранение не удалось, экран остаётся прежним.

4. **Кому что передаёт:**
   - `LegacyBoardStats` получает весь список `tasks` для счётчиков (`:114`);
   - три `TaskColumn` получают задачи своего статуса и колбэки `onEdit`, `onMove`, `onDelete` (`:118–120`). Колонка передаёт их дальше в `LegacyTaskCard`;
   - `TaskForm` получает редактируемую задачу (или ничего, если задача новая), `onSubmit`, `onCancel` и текст ошибки;
   - `ConfirmDialog` получает заголовок, текст и действие для удаления или сброса.

5. **Одна переменная на три режима формы.** `activeForm` равна `null`, когда форма закрыта, строке `'create'`, когда создаётся новая задача, и самой задаче, когда она редактируется. По этому значению `saveTask` решает, вызывать `create` или `update`.

6. **Опасные действия идут через подтверждение.** Кнопки «Удалить» и «Восстановить пример» ничего не делают сразу, а только записывают намерение в `pendingConfirmation`. Реальное действие выполняется после нажатия в `ConfirmDialog`.

7. **Ошибки показываются в двух местах.** Ошибка сохранения формы видна внутри формы (`formError`), и форма остаётся открытой. Ошибки загрузки, перемещения, удаления и сброса показываются над доской (`operationError`, `role="alert"`).

8. **Где используется.** Только в `src/app/App.tsx:12`. По умолчанию `App` передаёт туда репозиторий на `localStorage` (`src/app/App.tsx:10`), а тесты подставляют свой.

**Неочевидное:**
- Перемещение идёт по кругу: «Готово» → «Запланировано» (`:17–21`). Кнопка «Переместить» у готовой задачи возвращает её в начало.
- Флаг `active` в `useEffect` (`:32`) не даёт записать результат загрузки, если компонент уже размонтирован или сменился репозиторий.
- `input as CreateTaskInput` (`:50`) — приведение типа без проверки. TypeScript здесь не гарантирует, что при создании форма вернула обязательные поля, это держится на режиме `activeForm`.
- Отдельного состояния загрузки нет. Пока `load()` не ответил, доска пустая, а счётчики показывают 0.
